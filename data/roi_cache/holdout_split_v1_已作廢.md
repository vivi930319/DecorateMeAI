# ⚠️ 保留集 v1 已於 2026-08-06 作廢

**不要再用 `holdout_split_v1.json` 評估線上模型。**

## 為什麼

保留集的意義是「模型沒看過的考卷」。2026-08-06 決定讓線上模型吃到合併後的全部資料
（多出來的 101 張眼型照片確實有幫助，見 `模型訓練記錄_2026-08-06.md` §5.4.2），
而「全部資料」包含 v1 保留的那 613 張。

所以從 bundle `20260806` 開始，**線上模型訓練時看過 v1 的每一張照片**。
拿 v1 去評估它，量到的是記憶而不是泛化能力。

這是刻意的取捨：線上模型不該為了保留一份考卷而永久放棄 27% 的訓練資料。

## 哪些數字還有效

`models/holdout_scores.json` 裡的評估分兩種：

| 標籤 | 訓練時看過 v1 嗎 | 還能不能比較 |
| --- | --- | --- |
| `sweep_A_eye_s*`、`sweep_B_eye_s*` | 否 | ✅ 有效，這是「101 張有沒有幫助」的證據 |
| `A_合併前_ConvNeXt`、`B_合併後_ConvNeXt` | 否 | ✅ 有效 |
| `sweep_B_nose_s*` | 否 | ✅ 有效，雜訊底線的證據 |
| `線上_ConvNeXt_bundle20260731` | **是** | ❌ 當時就標為洩漏，只能當上限參考 |
| `final_全資料_s42/43/44` | **是** | ⚠️ 只能三者互比（都同樣洩漏），不能當泛化指標 |

前三類之間的比較永遠有效，因為那些模型確實沒看過 v1。

## 下次要怎麼做

資料再擴充時建立 v2，並在訓練紀錄裡寫明版本轉換：

```powershell
.\.venv\Scripts\python.exe tools\build_holdout_split.py --version v2
```

`build_holdout_split.py` 會拒絕覆蓋既有版本，所以 v1 的檔案會留著——它仍是上面那些
歷史評估的依據，不要刪。

**v2 建立之後，線上模型就要改成只用 train 部分訓練**，否則會重蹈覆轍：
每次都為了多那點資料而把基準花掉，永遠沒有可比較的歷史。
