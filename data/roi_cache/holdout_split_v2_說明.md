# 保留集 v2（2026-08-28 建立）

`holdout_split_v2.json`：613 / 2298 筆（26.7%），涵蓋 197 個 identity，18 個類別全部有代表。

## v2 的內容與 v1 完全相同

同一份 `index.json`、同一個 seed 42、同一個 ratio 0.20，所以切出來是同一批照片：

| | v1 | v2 |
| --- | --- | --- |
| 樣本（去重後 sha256） | 2135 | 2135 |
| holdout | 542 | 542 |
| 兩者 holdout 重疊 | — | **542（100%）** |
| v2 有而 v1 沒有的樣本 | — | **0** |

**這不是失誤，但它決定了 v2 現在能做什麼、不能做什麼。**

## 現在的線上模型不能用 v2 評分

v1 作廢的原因（見 `holdout_split_v1_已作廢.md`）是 2026-08-06 讓線上模型吃下全部資料，
其中就包含這 542 張。v2 既然是同一批照片，**線上模型一樣全部看過**。
拿 v2 去評線上模型，量到的是記憶，不是泛化能力。

## v2 能做什麼

**從 2026-08-28 起的每一次訓練都排除它**，所以之後訓練出來的模型彼此之間可以比較。
基準是往前生效的，不是回溯的。

`tools/training_worker.py` 的 `--holdout-split` 預設值就是 `v2`，不需要每次記得加。
預設而不是選項是刻意的：v1 正是因為「這次先不加，資料比較重要」而花掉的，
而忘記一次的代價是整份基準作廢。要停用必須明講 `--holdout-split ''`。

## 什麼時候該建 v3

**只有在 `index.json` 真的新增照片之後**。資料沒變就重切只會得到同一份切分，
換個檔名不會讓任何模型變成沒看過它。

```powershell
.\.venv\Scripts\python.exe tools\build_holdout_split.py --version v3
```

建好之後把 `training_worker.py` 的 `--holdout-split` 預設值改成 `v3`，
並在訓練紀錄裡寫明從哪一版換到哪一版——換基準等於換考卷，跨版本的數字從那裡斷開。
