## 名詞速查（先看這個，後面就順了）

| 術語 | 白話解釋 |
| --- | --- |
| **標籤 label** | 人工標註的正確答案，例如這張照片是「圓眼」 |
| **類別 class** | 一個部位可能的答案有哪些，例如眼型有 4 個類別 |
| **訓練集 / 驗證集** | 訓練集拿來學，驗證集拿來考試。考題不能提前給模型看過 |
| **macro accuracy** | 每個類別各自算對幾成，再平均。**每個類別權重相同** |
| **過擬合 overfitting** | 模型把訓練資料背起來了，換沒看過的資料就崩 |
| **洩漏 leakage** | 考題不小心混進了練習題，分數會虛高 |
| **ROI** | Region of Interest，從整張臉裁出「只有眼睛」「只有鼻子」的小圖 |
| **landmark** | 臉上的關鍵點座標，例如眼角在哪、鼻翼在哪 |
| **CNN** | 卷積神經網路，最常見的影像模型 |
| **遷移學習 transfer learning** | 拿別人在大資料上訓練好的模型，改最後一層來做自己的任務 |
| **交叉驗證 cross-validation** | 把資料切成 k 份，輪流當考題，考 k 次取平均 |
| **標準差 std** | 分數的波動程度。std 大代表這個結果不穩 |

# 第 0 步：問題是什麼

要從一張正面照判斷五件事：臉型、眉型、眼型、鼻型、唇型。

**這不是「貓 vs 狗」那種題目。** 貓和狗在物理上是互斥的，但「杏仁眼 vs 桃花眼」
的界線是人定的，而且**不同的人會標出不同答案**。這件事在第 5 步會變成主角。

資料規模：照片約 2300 張，每個部位可用 269～676 張，每個類別約 100～225 張。
**這在深度學習裡算非常小。** 一般 ImageNet 訓練是 120 萬張。

# 第 1 步：世代 0 — 用數學公式硬判（失敗）

## 做了什麼

用 MediaPipe（Google 的臉部關鍵點工具）抓出臉上 468 個點的座標，
算幾個比例，然後用 if-else 判斷。

例如眼型看三個數字：

```
ear            眼睛的「開合比」= 眼睛高度 ÷ 眼睛寬度
angle          眼角的傾斜角度
ratio_to_face  眼睛相對整張臉有多大
```

然後寫死門檻：`if ear < 0.264: return "細長眼"`。

## 出了什麼事

**抽驗眉型，發現規則式對每一張照片都吐「彎月眉」。**

資料夾裡明明有一字眉、落尾眉，但程式一個都判不出來。

## 怎麼發現的

拿資料夾的標籤（人工標的）跟程式的輸出比對，**一致率只有 33%**——
而且錯的方式很整齊：全部答同一個。

## 根本原因：死碼

把每個門檻拿專案的真實資料去驗證觸發率，發現有些條件**永遠不可能成立**：

```
瞇縫眼 需要 ratio_to_face < 0.12   但資料中實際最小值是 0.194
窄鼻   需要 ratio_width  <= 0.205  但實際分布根本不在這個範圍
```

**這叫死碼（dead code）**——那幾行 `return "瞇縫眼"` 永遠不會被執行到。

原因是那些門檻是從 **CelebA**（一個以西方人臉為主的公開資料集）調出來的，
套到本專案的亞洲人臉直接失效。

## 學到什麼

> **這類錯誤不會報錯，只會安靜地讓某些類別再也不出現。**

程式沒有 crash、沒有 exception、日誌乾乾淨淨。要發現它，只能主動去量
「每個分支被觸發幾次」。這個教訓在後面會一再出現，本專案把它叫做
**靜默降級（silent degradation）**。

## 額外的收穫

這次抽驗同時證明了另一件事：**標籤不是規則式產生的**。

這很重要。因為 repo 裡有一條自動標註的工具鏈，如果標籤是程式產生的，
那後面訓練 CNN 只是在「模仿一個壞掉的規則」，所有分數都沒有意義。
實測否定了這個懷疑——標籤是可信的人工標註。

# 第 2 步：世代 1 — 整張臉餵 CNN（失敗）

## 做了什麼

把整張臉縮成 160×160 的圖，餵給 CNN，讓它自己學。

## 兩個結構性缺陷

**缺陷一：餵整張臉去判鼻型。**

160×160 的圖裡，鼻子只佔幾十個像素。模型很難從那麼少的像素判斷鼻型，
但它會找到別的捷徑——**去學「這個人是誰」**。因為同一個人的多張照片標籤一樣，
只要認出人就能猜對。

**缺陷二：隨機切分。**

把所有照片隨機分成訓練集和驗證集。但同一個人有多張照片，
隨機切分會讓**同一張臉同時出現在兩邊**。

模型在驗證集上看到的是它訓練時背過的臉 → 分數虛高。

## 這一版沒有留下可信的數字

兩個缺陷都會讓分數往上虛報，所以世代 1 的分數全部作廢。

# 第 3 步：世代 2 — 裁 ROI + 按人切分

## 改動一：餵部位 ROI，不是整張臉

用 landmark 定位，從原圖裁出各部位的小圖：

```
臉型  128×128（要涵蓋整個輪廓）
其餘   96×96（局部特寫）
```

這樣模型看到的就只有「一雙眼睛」，沒辦法靠認人作弊。

## 改動二：按身分（identity）切分

**核心想法：同一個人的所有照片，只能全部在訓練集，或全部在驗證集。**

做法：
1. 用 InsightFace（人臉辨識模型）抽出每張照片的 512 維「人臉特徵向量」
2. 兩張照片的向量夠像（cosine 相似度 > 0.45）就視為同一個人
3. 聚類完成後，同一個人整組分到同一邊

> **cosine 相似度**：把兩個向量想成箭頭，看它們夾角有多接近。
> 1.0 是完全同方向，0 是垂直。

## 量出洩漏有多大

刻意**同時跑兩種切分**當對照：

| 部位 | 隨機切分 | 按人切分 | 差距 |
| --- | --- | --- | --- |
| face_shape | 0.588 | 0.475 | **+0.113** |
| eye_shape | 0.481 | 0.378 | +0.103 |
| nose_shape | 0.771 | 0.666 | +0.105 |

**隨機切分的分數高出 0.1 以上，而那 0.1 完全是假的。**

## 這一輪最重要的發現：分數本身不可靠

把訓練回合數（epochs）從 25 加到 40，結果是：
**三個部位變差、兩個變好，方向隨機。**

原因：驗證集只有 43～105 張，**一張分類結果就值 1～2 個百分點**。
分數的隨機波動大約 ±0.1。

> **「0.53 vs 0.47」這種差距在當時的資料量下沒有意義。**

這個認知直接催生了下一步。

# 第 4 步：世代 3 — 交叉驗證與資料清理

## 建立 5-fold 交叉驗證

**5-fold 是什麼：** 把資料按身分切成 5 份，輪流拿其中 1 份當考題、其餘 4 份當練習，
考 5 次。每張圖都恰好當過一次考題。

好處：
1. 每張圖都被驗證過，不會因為剛好抽到簡單的考題而虛高
2. 得到 5 個分數，可以算**標準差**——知道這個結果穩不穩

## 然後發現資料本身有問題

**發現一：314 個重複檔**

對 1908 個檔案做 MD5 內容比對（把檔案內容算成一個指紋）：

- 254 組內容**逐位元組相同**
- 其中 195 組是**同一張圖出現在兩個不同類別的資料夾**

```
丹鳳眼/IMG_3603.jpg   ==   鳳眼/IMG_3603.JPG
```

多數不是標註打架，而是「類別合併只做了一半」——舊類別的圖被**複製**到新資料夾，
舊資料夾沒刪。

**為什麼這很嚴重：** 同一份像素被切到訓練集與驗證集兩邊，
模型在考試時看到的是它背過的東西。舊紀錄的鼻型 0.828、眉型 0.667 都出自這種狀況，
**不是真實表現**。

**發現二：identity map 過期，鼻型的驗證幾乎是空的**

寬鼻有 98 張，但**只有 11 張**曾經進過驗證集。
也就是說「鼻型 macro 中，寬鼻那一半是建立在 11 張圖上」——那個數字沒有意義。

**發現三：窄鼻的鼻翼比標準鼻還寬**

量出來的鼻翼寬度中位數：

```
寬鼻 0.310  >  窄鼻 0.291  >  標準鼻 0.283
```

**「窄鼻」竟然比「標準鼻」還寬。**

標註者判斷「窄鼻」時看的顯然不是鼻翼寬度（可能是鼻頭大小或鼻樑高度），
但模型只看得到鼻翼。結果是 33 個標準鼻裡有 30 個被判成窄鼻，**整個類別塌陷**。

修法：把窄鼻併進標準鼻，變成兩類。重訓後恢復正常。

## 學到什麼

> **在調模型之前，先確認資料是對的。**
>
> 世代 3 花了整輪在清資料，沒有產出新模型——但在那之前的所有分數都是假的。

**這也是第一次遇到「類別定義本身有問題」。** 不是模型不夠強，
是那個類別的定義跟模型看得到的東西對不上。

# 第 5 步：世代 4 — 三種方法同台比較

## 把資料統一

訓練集原本散在三個資料夾，而 `prepare_roi_cache.py` 只讀其中一個
（第 29 行的路徑是寫死的）。有 58 張鼻型照片就這樣一直沒被用到。

全部併入同一個資料夾，全程只搬不刪、每步都有 CSV 紀錄，最終稽核 **0 張照片遺失**。

## 三種方法對決（同一組 fold，可直接比較）

| 部位 | 幾何決策樹 | CNN | DINOv2 |
| --- | --- | --- | --- |
| face_shape | 0.445 | **0.470** | 0.424 |
| brow_shape | 0.448 | 0.490 | **0.543** |
| eye_shape | 0.379 | 0.388 | **0.473** |
| nose_shape | 0.782 | 0.827 | **0.846** |
| lip_shape | 0.336 | **0.485** | 0.446 |

**唯一站得住的結論：幾何決策樹五個部位全部墊底**，而且是在它已經重新校準過之後。

## 世代 3 的結論被推翻

世代 3 曾經因為「規則式在眼型與臉型贏過 CNN」而讓規則式上線。
資料換了一批之後：

| 部位 | 07-24（規則 vs CNN）| 07-29（規則 vs CNN）|
| --- | --- | --- |
| 眼型 | 0.406 vs 0.332 → 用規則式 | **0.379 vs 0.388** CNN 反超 |
| 臉型 | 0.544 vs 0.477 → 用規則式 | **0.445 vs 0.470** CNN 反超 |

> **教訓：「規則式比較穩」是錯覺。**
> 它的門檻同樣是從資料擬合出來的，只是擬合過程不叫「訓練」。
> 資料一變，它一樣會退步，而且**沒有任何機制提醒你**。

## 這一輪真正的發現：瓶頸是類別定義

眼型從 6 類合併成 4 類，macro 從 0.388 跳到 0.523（**+0.135**）。

**同一天量到的所有「換模型／調參數／加資料」加起來都沒有這個數字大。**

證據鏈：程式偵測到「內容完全相同、卻被標成不同類別」的樣本共 94 組，眼型佔 57 組：

```
圓眼 vs 杏仁眼      17 組
細長眼 vs 鳳眼      17 組
杏仁眼 vs 桃花眼     7 組
```

**標註同學自己就分不開這三類。** 模型學不會的東西，是因為那條邊界本來就不存在。

# 第 6 步：世代 5 — 先量雜訊，再談改進

## 為什麼要量雜訊底線

前面一直在比較「0.47 vs 0.52 哪個好」，但**如果同一組設定重跑兩次就會差 0.05，
那所有比較都沒意義**。

所以拿同一組設定完整重跑一次，只有隨機性不同：

| 部位 | 第一次 | 第二次 | 差 |
| --- | --- | --- | --- |
| face_shape | 0.516 | 0.500 | −0.016 |
| nose_shape | 0.881 | 0.866 | −0.015 |
| lip_shape | 0.492 | 0.504 | +0.012 |

**雜訊底線 ±0.016。** 從此所有結論都以這個為尺：**差距小於它就是「沒有差別」**，
不管數字看起來多誘人。

> **這一步應該更早做。** 在有這把尺之前，前面所有「A 比 B 好」的判斷都是憑感覺。

## 超參數：原本是訓練不足

| 設定 | 五部位平均 |
| --- | --- |
| 基準 20ep / 3e-4 | 0.532 |
| **40ep / 6e-4** | **0.566** |
| **40ep / 3e-4** | 0.562 |
| 40ep / 1e-4 | 0.537 |
| 20ep / 1e-4 | 0.514 |

原本的假設是「驗證分數震盪代表學習率太高」，往下調結果**全面變差**——
真相是**訓練不足**，20 個回合還沒收斂就停了，學習率調低讓收斂更慢，錯上加錯。

> **那組反向對照（6e-4）救了這個判斷。**
> 只試假設的方向，會停在「調低沒用」然後放棄。
> **每次調參都要有一組往相反方向的對照。**

## 集成為什麼沒用

試過「CNN 信心夠高就用 CNN，否則退回規則式」（叫 hybrid）。
**五個部位全部被拉低。**

演算法挑出來的最佳門檻多數是 **0.00**——意思是「無論 CNN 多沒把握都別聽規則式」。

原因：**兩者錯的是同一批樣本。** hybrid 假設「CNN 沒把握時規則式會答對」，
但 CNN 沒把握的正是界線模糊的臉，規則式在那些臉上一樣分不開。

# 第 7 步：世代 6 — 一場事故

## 事情經過

```
07-29 16:47  建 identity_map.json —— 用照片的「絕對路徑」當鍵
07-30 00:31  把 杏仁眼/桃花眼 的檔案「實體搬進」桃杏眼 資料夾 → 路徑變了
07-30 01:43  把 M型唇 的檔案實體搬進 花瓣唇 → 路徑變了
07-30 01:06+ 在這之後跑的每一次交叉驗證
```

程式查不到路徑就給 `identity = -1`，而 `-1` 的規則是
**「聚類失敗，一律留在訓練集，永遠不進任何一折的驗證集」**——
那個設計本身是對的（不知道是誰的照片，就不能拿它當考題）。
錯的是**搬完檔案沒有重建身分聚類**。

## 後果

| 部位 | 類別 | 總張數 | 能進驗證集 |
| --- | --- | --- | --- |
| eye_shape | **桃杏眼** | 221 | **1 張** |
| lip_shape | **花瓣唇** | 225 | 131 張 |

全資料集共 **315 筆**掉成 `-1`。

而那 1 張桃杏眼**剛好答對**，於是這個類別的 recall 被記成 **1.000**——
macro 有五分之一的權重是一張圖撐出來的。

## 為什麼撐了那麼久沒被發現

1. **不報錯。** `-1` 是合法值，訓練照跑、模型照匯出、分數照印
2. **分數看起來很合理。** 桃杏眼 macro 0.466，比 6 類的 0.388 進步，
   方向符合「合併有效」的預期——**符合預期的數字最不會被檢查**
3. **總分幾乎沒變。** 重跑後是 0.463。抽查總分會覺得沒問題，
   真正壞掉的是**單一類別的 recall**（1.000 → 0.633）

## 怎麼發現的

重新讀專案文件時注意到「§十 重現方式」第 1 步是重建身分聚類，
但檔案時間戳顯示 identity_map 比資料夾異動早了 8 小時。
去數 `identity == -1` 的筆數，就看到 315。

## 修法

1. 重建身分聚類 → `-1` 從 315 筆降到 **2 筆**（那 2 張是真的偵測不到臉）
2. 全套流程重跑，所有數字換掉

## 學到的通則

> **合併類別如果是實體搬檔，identity map 的路徑鍵就全部失效。
> 合併類別與重建聚類是同一個動作的兩半，不是兩件事。**

判斷方法只有一個數字：

```
identity == -1 的比例    正常 < 0.1%（2/2311）
                         出事 13.6%（315/2311）
```

**每次重建快取後看這個數字，比看 macro accuracy 重要。**

2026-07-31 的細長眼合併改用**對照表**（只改一行程式，不動檔案），
路徑完全沒變，`-1` 維持 2 筆。

# 第 8 步：世代 7 — 架構對照，推翻核心假設

## 一直以來的假設

從世代 1 開始，這個專案都假設「資料太少所以要用小模型」，
所以選了 MobileNetV3-small（150 萬參數）。

**這個假設從來沒有被實際測試過。**

## 實測五種 CNN 架構

同一組 5-fold、同樣 40 epochs、同樣學習率：

| 架構 | 參數量 | face | brow | eye | nose | lip |
| --- | --- | --- | --- | --- | --- | --- |
| MobileNetV3-small | 1.5M | 0.521 | 0.511 | 0.562 | 0.849 | 0.553 |
| EfficientNet-B0 | 4.0M | 0.564 | **0.612** | 0.607 | 0.855 | 0.561 |
| ResNet-50 | 23.5M | **0.604** | 0.587 | 0.660 | 0.877 | 0.578 |
| **ConvNeXt-Tiny** | 27.8M | 0.561 | 0.603 | **0.693** | **0.881** | **0.640** |
| AlexNet | 57.0M | 0.494 | 0.422 | 0.628 | 0.867 | 0.396 |

## 結論：小模型假設是錯的

**三個大架構在五個部位上全部贏過 MobileNetV3——15/15。**

錯在把「參數量 > 樣本數 → 過擬合」的通則套到**遷移學習**上。
遷移學習微調的是**已經學好的表示**，不是從零學。
更好的 backbone 提供更好的起點，這個效果大於容量帶來的過擬合風險。

提升幅度超過本專案任何其他改動：

```
換架構（ConvNeXt-T）  眼型 +0.131  眉型 +0.092  唇型 +0.087
合併類別（先前最佳）   +0.068 ~ +0.069
調學習率               +0.022
```

## AlexNet：過擬合長什麼樣子

AlexNet 不是平均低，是**標準差爆掉**：

```
face  0.494 ± 0.145   逐折 0.628, 0.542, 0.213, 0.573, 0.514  ← 一折崩到 0.213
lip   0.396 ± 0.136   逐折 0.578, 0.250, 0.328, 0.283, 0.540
```

其他架構的 std 都在 0.02～0.07。

原因：**5700 萬參數裡有 5800 萬在最後三層全連接層**（比整個 ConvNeXt-Tiny 還多），
那正是小資料最容易過擬合的地方。

> **這是很好的教學案例：過擬合在交叉驗證上的表現不是「平均差」，而是「不穩定」。**

# 第 10 步：這個專案學到的方法論

## 10.1 先確認資料，再談模型

世代 3 花了整輪在清資料，沒有產出新模型——但在那之前的所有分數都是假的。
314 個重複檔、過期的 identity map、塌陷的窄鼻類別，任何一個都足以讓結論反向。

## 10.2 「分數變好」要先問「雜訊有多大」

在驗證集只有 43～105 張的規模下，**0.53 vs 0.47 沒有意義**。
判斷標準：**領先幅度要大於標準差**。

## 10.3 分數低不一定是模型的錯

四次遇到「類別定義本身有問題」：

1. 窄鼻的鼻翼比標準鼻還寬 → 類別塌陷
2. 丹鳳眼與鳳眼視覺上無法區分 → 大量跨類重複
3. 杏仁眼／桃花眼的界線不存在 → 合併後 +0.069
4. M型唇 recall 0.296、錯誤均勻散開 → 合併後 +0.068

**在調模型之前，先看混淆矩陣裡哪兩類在互相打架。**

但也要記得一個反例：**矩陣告訴你「這一類有問題」，不會告訴你「該併去哪裡」。**
M型唇最常被認成微笑唇，正確的合併對象卻是花瓣唇——那一步靠的是唇形定義。

## 10.4 靜默降級比報錯危險

本專案出現過至少六次：

- 幾何門檻是死碼 → 某些類別永遠不出現
- identity map 過期 → 合併後的類別整批退出驗證集
- DINOv2 head 寫到另一個目錄 → 差點拿舊 head 上線
- 下游對照表沒跟上分類表 → 英文代碼被寫進中文 prompt
- 鳳眼被顯示成已淘汰的「丹鳳眼」，撐了六天
- PRO 服務忘了解包 tuple → 每次分析都回 400，壞了一週

**修法一律是：讓它大聲失敗。**

## 10.5 不要用驗證集挑東西

用驗證集選超參數會讓分數虛高（本專案犯過一次，虛高 0.018）。
需要選門檻時採用**巢狀切分**：在訓練折內再切一次來選，不碰外層驗證集。

## 10.6 預設的資料增強可能是錯的

水平翻轉是影像分類的標準增強，但**落尾眉翻轉後會變成上揚眉**，等於餵錯標籤。
**領域知識要進到增強設定裡。**

## 10.7 說一個方法「行不通」之前，先確認量到的是方法本身

階層式臉型分類第一次量到 0.398，判定「行不通」。
後來發現是實作用了 `class_weight="balanced"`，導致每一層都「搶著開火」——
**鵝蛋臉 105 個樣本裡有 70 個在輪到它之前就被前兩層吃掉了**。

拿掉之後 0.398 → 0.435。**方法仍然不夠好，但第一次的結論指錯了原因。**
